# TJ-ToothAI

**口腔健康智能分析与报告系统**

TJ-ToothAI 将口腔图片采集、远程智能检测、可视化标注、综合报告和健康科普整合为一个 Web 应用。用户可以上传多张口腔照片或使用摄像头拍摄，补充信息后提交分析，查看标注图片与 AI 文字报告，并通过浏览器打印保存报告。

项目延续原网页“专业口腔医生助手，仅作学习展示”的定位，探索人工智能与口腔医学结合的应用流程。页面展示龋齿、牙结石、齿色、牙周炎、缺牙、补牙等分析方向；实际可识别类别及效果取决于所调用的模型与服务。本仓库不对原网页中的研究成果、机构应用或诊断准确率作额外保证。

仓库：[AIMedical51/TJ-ToothAI](https://github.com/AIMedical51/TJ-ToothAI) · 维护者：[AIMedical51](https://github.com/AIMedical51)

> 本项目用于学习、研究与功能演示，输出不替代专业口腔检查和诊断。当前没有用户登录和报告访问控制，请先使用脱敏测试数据在本机验证。

## 功能概览

| 功能 | 当前实现 |
| --- | --- |
| 项目展示 | 首页、关于页面、合作背景与服务介绍 |
| 图片采集 | 本地图片上传、浏览器摄像头拍照 |
| 多图管理 | 逐张添加、删除当前图片、前后切换 |
| 信息录入 | 姓名、性别、年龄，以及可选自述和诊断信息 |
| 综合检测 | 调用 Roboflow 远程模型，合并检测结果 |
| 结果展示 | 原图与标注图对照、中文类别标注 |
| 综合报告 | 结合检测结果和录入信息调用智能体生成文字分析 |
| 报告导出 | 打开可打印 HTML，通过浏览器打印或另存为 PDF |
| 二维码 | 独立服务生成报告访问二维码，可显示姓名并打印 |
| 健康科普 | 龋齿、牙周炎、牙结石、智齿分类页面；视频素材需补充 |
| 开发接口 | 单图、多图、单项检测、报告读取与二维码接口 |

主页中的六类服务是功能展示方向，不代表六个独立模型均已完成准确率验证。当前网页主流程展示标注图片和 AI 文字；旧代码中的评分报告不等同于主流程必然输出健康评分。

## 技术栈与处理流程

- **Web 服务**：Python、Flask、Jinja2。
- **前端**：HTML、CSS、JavaScript、Bootstrap、jQuery。
- **图像处理**：OpenCV、NumPy、Pillow、Supervision。
- **远程检测**：Roboflow Inference SDK；主流程调用远程模型。
- **文字报告**：同济智能体服务接口，需配置相应权限与凭据。
- **二维码**：独立 Flask 服务、`qrcode`、Pillow。
- **数据保存**：本地图片和 JSON/HTML 文件；当前没有数据库和账号系统。

```text
浏览器：上传图片 / 摄像头拍照 + 信息录入
                    |
                    v
             Flask 主服务 :5000
                    |
          +---------+----------+
          |                    |
          v                    v
   Roboflow 远程检测       本地 var/ 运行数据
          |
          v
   合并检测结果、绘制标注
          |
          v
   智能体文字分析 -> 综合报告 -> 浏览器打印 / 保存 PDF
                                   |
                                   v
                       二维码服务 :16666 -> 扫码访问报告
```

主网页流程不依赖本地模型权重或 GPU，但需要网络以及可用的远程服务权限。仓库还保留了历史模型和实验脚本；它们不属于下面的最小启动流程，也没有随仓库提供可直接使用的权重下载地址。

## 快速开始

以下命令适用于 macOS / Linux，均从仓库根目录执行。推荐使用 **Python 3.11**。主应用采用的 `inference-sdk==0.37.1` 要求 Python 版本低于 3.13；不要直接使用系统最新 Python 创建环境。

版本范围可查阅 [SDK 发布元数据](https://pypi.org/project/inference-sdk/0.37.1/)。

已在 macOS ARM64 / Python 3.11.18 验证依赖安装、10 项离线回归测试与服务入口导入；真实模型和智能体服务尚未完成端到端验证。旧的 `requirements_tjtoothai_env.txt` 是历史环境快照，不是主网页服务的安装入口。

### 1. 获取源码并创建主应用环境

```bash
git clone https://github.com/AIMedical51/TJ-ToothAI.git
cd TJ-ToothAI
python3.11 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r www/tjtooth/requirements-web.txt
```

已有源码时直接进入仓库根目录，从创建虚拟环境开始执行即可。不需要 npm 构建步骤。

### 2. 首次创建配置

仅在根目录还没有 `.env` 时执行，**不要覆盖已有配置**：

```bash
cp .env.example .env
chmod 600 .env
```

用本地编辑器填写 `.env`，至少配置 `ROBOFLOW_API_KEY` 和 `TONGJI_AGENT_API_KEY`，并确认对应服务地址、模型权限及智能体配置适合自己的账号。真实密钥仅保留在本机或部署环境，不能写进 README 或提交到 Git。

主应用自动读取仓库根目录 `.env`，已经存在的进程环境变量优先。没有配置密钥时仍可查看首页，但检测和智能报告不可完整使用；二维码服务不依赖这两项凭据。

公开仓库只包含 `.env.example`，不包含实际 `.env`、私钥或含旧密钥的备份。宣传用的联系方式、人物介绍和固定二维码按维护者要求保留；生成公开发布包的方法见 [GitHub 发布指南](docs/GITHUB.md)。

### 3. 启动主应用

```bash
python www/tjtooth/app.py
```

浏览器打开 [本机首页](http://127.0.0.1:5000)。默认监听 `127.0.0.1:5000`，停止服务使用 `Ctrl+C`。可先检查首页、检测表单、科普分类和页面导航，再使用脱敏测试图片验证推理。

### 4. 启动二维码服务

另开终端，进入同一仓库根目录，创建独立虚拟环境：

```bash
python3.11 -m venv .venv-qr
source .venv-qr/bin/activate
python -m pip install --upgrade pip
python -m pip install -r qrcode-server/requirements.txt
python qrcode-server/app.py
```

默认监听 `127.0.0.1:16666`。访问 [二维码健康检查](http://127.0.0.1:16666/health) 应返回 `{"status":"ok"}`。主应用默认使用该服务生成报告二维码。

**二维码服务不会读取根 `.env`。** 如需修改它的背景图、字体、监听地址或端口，通过启动终端的环境变量或进程管理器注入，具体配置见 [部署说明](docs/DEPLOYMENT.md)。

## 网页使用说明

### 1. 选择或拍摄图片

从首页点击“开始检测”，或打开 [检测页面](http://127.0.0.1:5000/caries)。点击“上传图片”选择一张图片，再通过“添加图片”逐张追加；当前文件控件不支持一次多选。建议使用可被 OpenCV 解码的 JPG / PNG 图片。

也可以点击“打开摄像头”，允许浏览器访问设备后点击“拍摄照片”。照片会加入列表，随后关闭摄像头。摄像头通常要求 localhost 或 HTTPS 安全上下文，参见 [MDN：getUserMedia](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia)。

用左右箭头切换图片，用“删除当前”移除错误图片。尽量让同一次提交的图片来自同一测试对象；多角度图片会参与同一份综合报告。

### 2. 填写信息并提交

展开“患者信息录入”，填写必填的**姓名、性别、年龄**。民族、患者自述、医生诊断与建议、诊断结论为可选字段。演示时使用虚构或脱敏信息，避免录入无关个人数据。

点击“开始检测并生成报告”。页面会上传全部图片与表单信息，等待远程检测和报告处理。进度条是前端模拟动画，不表示真实推理完成百分比；不要依据进度条推断服务是否已经成功。

### 3. 查看标注与报告

成功后可切换原图与对应的标注结果，点击“查看详细报告”在新窗口浏览综合结果。报告是否生成取决于检测结果及外部服务响应；没有检测框或没有报告链接，**不代表已经排除疾病或确认口腔正常**。

智能体不可用时，可能保留检测结果而没有完整文字分析。可选表单字段不一定都参与智能体分析，实际请求字段和异常行为见 [API 参考](docs/API.md)。

### 4. 打印、保存 PDF 与扫码

点击“下载 PDF 报告”，允许浏览器打开弹窗，在可打印页面中选择“打印”并另存为 PDF。该按钮打开的是 HTML 打印页面，不是服务器直接返回 PDF 文件。

二维码服务启动后，点击报告页的二维码按钮生成并打印报告访问二维码。手机必须能够访问二维码内的报告网址；手机扫码得到 `127.0.0.1` 或 `localhost` 时，访问的是手机自身，无法直接打开电脑上的报告。

跨设备使用需要配置可访问的站点地址、`PUBLIC_BASE_URL` 和 `QRCODE_API_URL`，并设置访问控制与 HTTPS。具体步骤见 [部署说明](docs/DEPLOYMENT.md)。科普入口使用固定二维码图片，更换站点域名后需重新生成该图片。

### 5. 重新检测与科普浏览

“重新检测”会清空当前检测结果，**保留已选图片和表单内容**。切换测试对象前应删除旧图片并更换信息，必要时刷新页面，避免混用资料。

导航中的“科普视频”提供龋齿、牙周炎、牙结石、智齿分类。当前源码包缺少首页演示视频与科普 MP4 文件；补充有权使用的素材后才能实际播放，素材路径见 [部署说明](docs/DEPLOYMENT.md)。

## 配置与数据目录

主应用常用配置如下，完整说明和二维码服务配置见 [部署说明](docs/DEPLOYMENT.md)：

| 配置项 | 用途 / 默认值 |
| --- | --- |
| `ROBOFLOW_API_KEY` | 远程检测凭据；需自行配置 |
| `ROBOFLOW_API_URL` | Roboflow 推理服务地址 |
| `TONGJI_AGENT_API_KEY` | 智能体服务凭据；需自行配置 |
| `TONGJI_AGENT_BASE_URL` | 智能体接口根地址 |
| `TONGJI_AGENT_USER_ID` | 智能体请求使用的用户标识 |
| `TJT_DATA_DIR` | 运行数据根目录，默认仓库根 `var/` |
| `TJT_FONT_PATH` | 中文标注字体路径 |
| `TJT_HOST` / `TJT_PORT` | 默认 `127.0.0.1` / `5000` |
| `PUBLIC_BASE_URL` | 对外访问的主站地址；本机使用可留空 |
| `QRCODE_API_URL` | 默认 `http://127.0.0.1:16666/v1/create-qr-code/` |

运行时会创建 `var/inputs/`、`outputs/`、`patient_info/`、`reports/`、`annotated_images/` 和 `html_reports/`。这些目录可能包含照片、信息和报告，已纳入忽略规则；不要上传到 GitHub，也不要把整个仓库根目录配置成公开静态文件目录。

目前没有自动清理策略。部署者需要决定保存期限、备份与删除方式；停止服务不等于删除历史数据。修改 `TJT_DATA_DIR` 后，也应确认新目录不会被提交或公开。

## 限制与常见问题

| 情况 | 说明与检查方向 |
| --- | --- |
| 首页可打开，检测失败 | 检查凭据、模型访问权限、网络和服务地址；页面可用不代表外部推理已配置 |
| 检测完成但没有报告 | 可能没有有效检测结果；不能据此判定健康，检查响应与服务日志 |
| 图片有标注，文字分析为空 | 检查智能体配置、权限、响应格式及服务状态 |
| 中文标签缺字 | 配置可用的中文字体；二维码服务另用 `QRCODE_FONT_PATH` |
| 摄像头无法打开 | 检查浏览器授权、设备占用及 localhost / HTTPS 上下文 |
| PDF 没有自动下载 | 允许弹窗，在打印页通过浏览器另存为 PDF |
| 二维码无法显示 | 检查独立服务和 `QRCODE_API_URL`；HTTPS 页面应使用 HTTPS 或同源代理 |
| 视频无法播放 | 当前没有提供 MP4 素材，需自行补齐并确认使用权限 |

当前没有登录、报告所有者校验、完整上传约束或生产级访问控制。图片会发送到远程检测服务，检测结果及部分录入信息会发送到智能体；二维码服务也会接收报告地址和可选姓名。使用真实数据前，应完成相应授权与部署保护。

首页原有的 Coze 聊天浮窗因包含长期凭据已移除；如需恢复，应先实现受控鉴权。`/contact` 仍为遗留展示模板，没有实现表单提交。部分轮播资源缺失，历史模板也保留了静态资源路径问题，不能视为全部页面已经完成浏览器兼容验证。
